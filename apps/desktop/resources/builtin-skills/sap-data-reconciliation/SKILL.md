# SAP 运维数据与接口对账

## 方法边界

SAP 没有一套适用于所有模块的统一对账模板；本 Skill 使用可追溯、可重算的通用工程方法。与 SAP 官方生命周期的关系及边界见 [official-basis.md](references/official-basis.md)。

## 工作流

1. 保留原件，不覆盖用户文件；不执行宏、外链或嵌入代码。
2. 清点来源、系统/Client、期间、导出时间、过滤条件、sheet/字段、行数和限制。
3. 冻结对账合同：一行含义、业务粒度、主键/匹配键、状态、时区、单位、币种、价格单位、符号、冲销/退货、容差和排除规则。
4. 建立保留原值的标准化副本，检查重复键、缺失键、类型、前导零、公式/合计行和不可转换项。
5. 分层比较：总量/金额守恒 → 业务分组 → 单据/项目 → 字段级；检查 join 是否意外放大。
6. 分类为匹配、仅左、仅右、值差异、口径差异、数据质量、待业务确认，并保留来源定位。
7. 对高影响差异和候选原因抽样回查原始证据；不能从相关性直接定根因。
8. 按 [reconciliation-output.md](references/reconciliation-output.md) 输出摘要、异常明细、证据和后续验证/修正清单。

## 质量与自定义

- 汇总必须能由明细重算；原值不能被标准化值覆盖。
- 业务口径、容差、字段别名、采样、Excel 模板和脱敏规则可由 Project/Case 规范覆盖，并标注来源。
- SAP 实时查询结果只有带系统、Client、时间和过滤条件才可作为当前证据。
- 批量修改、删除、重处理或 SAP 写回只生成待办清单，等待明确确认。
