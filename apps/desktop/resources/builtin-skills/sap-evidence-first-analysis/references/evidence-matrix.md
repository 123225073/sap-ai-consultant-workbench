# Incident / Problem 证据与 RCA 模板

## Incident 身份与业务影响

| Ticket | Project | SID/Client/环境 | 模块/组件 | 时间 | 优先级 | owner |
|---|---|---|---|---|---|---|

- 业务场景、入口/App、受影响流程和用户数。
- workaround、关键窗口、预期损失或 Go-Live 影响（适用时）。
- 期望结果、实际结果、错误文本和按时间顺序的复现步骤。

## 假设矩阵

| 假设 | 支持证据 | 反证 | 验证动作 | 结果 | 状态 |
|---|---|---|---|---|---|

状态使用：已确认 / 推断 / 假设 / 未确认 / 已排除。

## 根因与处置

现象 → 触发条件 → 直接根因 → 放大因素 → 业务影响。分别记录 workaround、永久修复、Change、复发监控和已排除原因。

## 关闭前检查

服务恢复、根因确认、修复验证、相关 Incident 聚合、业务确认、监控、遗留风险和 Knowledge 候选分别给状态；不得用“暂无反馈”代替验证。
