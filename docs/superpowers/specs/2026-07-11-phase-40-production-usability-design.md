# Phase 40 生产可用性与去 Demo 化设计

日期：2026-07-11

## 1. 目标

把当前“功能已经很多、但入口和状态仍像开发样机”的桌面工作台，收敛为个人 SAP 顾问可以长期使用的本地工具。

本阶段所说的“真实可用”必须同时满足：

1. 用户能从界面完成操作。
2. 结果真实持久化到本地状态或当前工作文件夹。
3. 重启应用后结果仍存在。
4. 失败时说明原因和下一步。
5. 不用演示数据、禁用按钮或阶段说明冒充能力。
6. 不突破 SAP 只读、密钥隔离、知识人工审核和外部发布确认边界。

## 2. 已确认问题

| 级别 | 问题 | 影响 |
|---|---|---|
| P0 | 新环境自动注入演示 Project、Case、Chat 和知识 | 用户无法区分真实数据和样例，产品第一印象失真 |
| P0 | Work 左栏同时常驻创建表单、项目操作、Project 和 Case | 导航、创建和管理混在一起，扫描成本高 |
| P1 | 右栏项目配置摘要与配置中心重复 | 低频设置长期占据案件工作空间 |
| P1 | Composer 同时常驻案件动作、权限、SAP、模型、Codex 和发送 | 最常用的自由对话入口被高级控制包围 |
| P1 | 规范中心存在“测试生成示例”和开发阶段说明 | 持久化能力真实，但页面仍表现成演示页 |
| P1 | 知识审核人写死为“演示用户” | 真实审核记录仍带演示身份 |
| P1 | 知识库展示不支持的演示文档解析队列 | 用户误以为 Word/PDF/Excel 已可解析 |
| P1 | 配置分区按钮实际保存整页草稿 | 一个区域的操作可能带上另一区域未确认内容 |
| P2 | README 和阶段文档仍声称应用尚未实现 | 文档不能作为真实交接依据 |
| P2 | `App.tsx`、`ConfigCenter.tsx`、`workspaceStore.ts` 过大 | 领域逻辑缺乏 locality，后续修改容易交叉回归 |

## 3. 目标信息架构

### 3.1 Work 左栏

- 顶部只保留 Work / Chat 切换和全局搜索。
- Work 导航只保留配置中心、规范中心、知识库三个中心入口。
- Project 以紧凑树展示；只有当前 Project 展开 Case。
- 新建 Project 和新建工作文件夹进入模态面板，不占据导航高度。
- Project 配置、创建工作文件夹、隐藏 Project 收进当前 Project 菜单。
- 历史演示 Project 进入独立“示例”分组，不和真实 Project 混排。

### 3.2 中间工作区

- 标题只显示当前工作文件夹与所属 Project。
- Notice 只在真实操作后显示，允许关闭，不长期占位。
- 对话和文件链接保持主内容优先。
- Composer 默认只显示输入框、上下文状态、模型和发送。
- 案件动作与权限进入一个“工作动作”弹出面板；选择动作后再显示确认区。

### 3.3 右栏

- 只展示当前工作文件夹文件和安全文本预览。
- 删除重复的项目配置摘要页签。
- 交接包是本地文件整理能力，不伪装成已经发布飞书。

## 4. 各中心真实能力

### 4.1 配置中心

- SAP、当前模型渠道、Feishu、Codex 分区保存，只提交当前分区普通配置。
- 测试按钮只受当前分区未保存内容影响。
- 模型渠道可添加、切换、验证和安全删除；删除必须二次确认并清理对应安全存储。
- 不显示密钥原文，不把连接器输出原样回传 renderer。

### 4.2 规范中心

- 模板复制、跨 Project 复制、编辑、保存、版本递增和差异均使用真实本地状态。
- 有未保存修改时，离开、复制模板或切换来源前提醒。
- 删除“测试生成示例”和底层提示词阶段说明。
- 案件生成继续读取当前 Project 规范摘要和版本。

### 4.3 知识库

- 新 Project 默认空知识库，不注入演示知识或演示解析任务。
- Markdown/TXT 和粘贴文本导入真实生成待确认候选。
- 候选可编辑、审核、发布、标记冲突、标记失效并引用到当前 Case。
- 审核身份使用“本机用户”，不再写“演示用户”。
- 不显示未实现的 Word/PDF/Excel 解析队列；已有历史任务只作为记录显示。

### 4.4 Chat 与案件文件

- Chat 可以选择已授权渠道和模型，但消息不进入 Project / Case。
- Work 的模型必须来自当前 Project 已验证渠道。
- 文件面板只预览当前 Case 内的受控文本文件。
- 案件动作的名称、确认保存位置和实际文件保持一致。

## 5. 数据兼容

- 不删除现有 `local-data`、历史 Project、Case、Chat、知识或文件。
- 停止新状态自动创建演示数据。
- 历史 `demo-s4hana` 仅在 UI 中降级到“示例”分组，用户仍可打开或自行隐藏。
- 新 Project 的默认工作文件夹使用“收件箱”，不再出现 `initial case`。

## 6. 明确不做

- SAP 写入、激活、传输、过账或删除。
- 自动发布 Feishu/Lark 云文档。
- 未经受控解析的 Word、PDF、Excel 全文导入。
- 删除现有用户数据或自动迁移密钥。
- 团队账号、登录、订阅或云端 SaaS。

## 7. 验收

1. Work 页面不再常驻创建表单、重复项目按钮和项目配置摘要。
2. Composer 的高级动作默认收起，自由对话仍可直接发送。
3. 新环境不出现“演示 S4HANA”“DEMO001”或演示知识。
4. 规范中心没有演示输出，保存后版本递增且案件读取新版本。
5. 知识导入、编辑、审核、发布、失效和案件引用可真实持久化。
6. 配置测试不会意外保存其他分区草稿。
7. 1440×920、1180×760 和窄窗口没有遮挡或横向裁切。
8. TypeScript、构建、Phase probes、安全预检和 `git diff --check` 全部通过。
