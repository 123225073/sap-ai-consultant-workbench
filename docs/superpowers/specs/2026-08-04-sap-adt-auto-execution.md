# SAP ADT 通用只读任务自动执行规范

## 目标

当用户在 Work 中明确提出 SAP 只读任务时，工作台应完成“识别意图、检查授权、选择客户项目连接、调用 ADT、取得真实结果、继续分析并生成本地成果”的闭环。连接测试通过不等于模型已获得工具授权，模型也不能自由跳过已经明确要求的 SAP 读取。

本实现参考 `shrek-abaper/sap-engineering-skill` 中 `sap-adt-cli` 的只读方法：先检查连接，再发现对象或字段，随后执行有界读取。工作台不直接运行第三方 Python 脚本，而是在 Electron main process 内封装等价的受控只读能力，以保留安全存储、Project 隔离、工具审计和 SAP 写入禁用边界。

## 执行规则

1. 只有明确的 SAP 读取动作才注册并进入自动 ADT 路径；普通办公消息以及含写入、修改、激活、过账、传输或删除意图的请求，本轮不向模型暴露任何 SAP 工具。
2. SAP 业务数据请求进入 `sap.search_objects` → `sap.read_data_preview` 字段发现 → `sap.read_data_preview` 有界读取；ABAP/DDIC 对象源码或元数据请求进入 `sap.search_objects` → `sap.read_object_evidence`。对象/源码意图优先于同一句话里出现的业务名词，避免把“查看 MARA 字段”误路由为业务数据查询。
3. 用户未在当前客户项目启用对应 AI 工具时，返回可操作的授权提示，不静默生成“待确认”草稿冒充执行结果。
4. 授权后，每一阶段都使用指定工具调用：语义目标不明确时先搜索对象或数据源，空搜索允许模型在最多三次内修改搜索词；明确业务数据对象可直接进入字段发现。源码或元数据对象只有在名称和对象类型都能可靠判断、且不需要额外定位信息时才直读；Function module 必须先搜索取得 Function group，未声明类型的自定义对象也必须先搜索。若 Repository Quick Search 在目标系统不可用，保留失败证据并强制进入固定对象读取或字段发现；模型提出的候选对象只有通过后续真实 ADT GET 验证后才能作为证据。字段发现阶段只允许 `operation=discover`，数据读取阶段只允许 `operation=read`，缺少或错用操作类型会在连接器执行前被拒绝。业务数据取得一次成功的有界读取后才恢复自动工具选择。
5. Data Preview 只接受结构化对象、字段、筛选和最大行数；模型不能提交任意 SQL。发现操作由系统规范为空字段、空筛选和一行上限。
6. SAP 返回需要 CSRF 会话时，使用只读 GET 获取令牌和会话 Cookie；Data Preview 端点不接受令牌获取时，回退到固定 T000 DDIC 元数据 GET。整个过程不执行 SAP 写入。
7. 最终回复必须标明系统、Client、数据源、筛选、返回行数和截断状态。受控工具成功结果可以作为证据；初始案件摘要不能覆盖或否认本轮真实工具结果。
8. SAP 工具失败必须把可操作的失败原因传回模型和用户；不得回退为普通聊天并暗示任务已完成。模型渠道若忽略指定工具并直接返回文本，该文本不作为成功结果，工作台明确报告渠道不兼容。
9. 对象读取覆盖 program、class、interface、function module、include、table、structure 和 CDS DDL，全部使用 `sap-adt-cli` 文档对应的固定 GET；Function module 搜索结果只提取脱敏后的 Function group，不把原始 URI 交给模型。

## 非目标与安全边界

- 不模拟 SAP GUI 事务码，不为 MB52 或其他单一事务建立专用硬编码业务功能。
- 不启用 SAP 写入、对象激活、传输创建/释放、过账、批量更新或任意程序执行。
- 不把 SAP 密码、会话令牌、Cookie、完整业务数据或原始工具请求写入日志、Git 或模型上下文。
- 完整明细保存在当前运维项目本地文件夹；模型只接收有上限的分析行。

- `scripts/phase64-sap-adt-auto-execution-probe.mjs` 覆盖意图重叠、混合“读取后生成本地成果”、未授权拦截、搜索→字段发现→有界读取、原始用户消息路由、各阶段指定工具、渠道忽略工具时拒绝假成功、连续失败终止，以及 CSRF/T000 会话兼容矩阵。
