# 生产加固经验复盘

日期：2026-07-18  
适用范围：SAP AI 顾问工作台后续开发、回归与发布

## 1. 复盘目的

项目目录只保留当前源码、最新发布包和仍有证明价值的验证证据。旧实现由 Git 历史追溯，失败经验沉淀为文档，不再通过复制发布目录、旧代码目录或重复截图长期保存。

## 2. 关键经验

### 2.1 发布包必须与唯一 Git 提交绑定

- 问题：多个 `final`、`patch` 和双击启动文件并存，用户容易打开旧版本，开发者也难以确认问题对应哪次构建。
- 根因：发布目录没有强制执行干净工作树、起始提交锁定和构建后提交复核。
- 规则：正式打包只允许从 clean worktree 开始；`BUILD-METADATA.json` 必须记录完整 commit、`gitDirty=false`、文件大小和 SHA-256。
- 规则：对外只推荐 Setup；Portable 只作为免安装选择。旧发布包不留在活动项目目录。

### 2.2 UI 状态必须服从用户已经完成的动作

- 问题：发送消息后输入框未立即清空、页面没有自动跟随、旧请求晚返回覆盖新配置、弹层不能点击空白处关闭。
- 根因：网络请求、持久化和界面状态混在同一个时序中，缺少明确的所有权和终态。
- 规则：用户发送后先完成本地乐观更新；输入立即清空并滚动到最新消息，失败时再恢复草稿。
- 规则：异步请求必须绑定不可预测的 `requestId` 或配置 revision；旧请求无权写回新状态。
- 规则：菜单、模型选择器和任务操作浮层统一支持外部点击与 Esc 关闭。

### 2.3 会话恢复不能依赖时间猜测

- 问题：相邻 Agent Turn 的晚到回复可能被误判为另一个中断任务的已保存结果。
- 根因：恢复逻辑曾使用消息时间和邻近关系推断关联。
- 规则：Work/Chat 持久消息与 Agent EventStore 使用精确 `agentTurnId` 关联；旧数据无法确认时保守标记，不自动重放。

### 2.4 外部能力的“发现”不等于“授权执行”

- 问题：MCP Server 自报只读属性可能被错误理解为可安全执行；CLI 登录成功也曾被误写成业务能力全部可用。
- 根因：配置、发现、验证、执行和发布几个阶段的产品文案与权限边界不清。
- 规则：外部 MCP 当前只允许 HTTPS 连接与 capabilities 发现，不执行第三方工具。
- 规则：模型、SAP、Feishu/Lark 分别记录真实验证范围，不用一个绿色状态替代全部能力结论。
- 规则：SAP 永远默认只读；任何写入、激活、传输、过账或删除都需要独立设计和用户明确确认。

### 2.5 本地文件夹选择只代表绑定，不代表授权读取

- 问题：早期“已有文件夹”只是页面内 Case 下拉框，不是 Windows 本地目录选择；修复后又需防止一次选择自动扩大模型读取范围。
- 规则：真实路径只留在 Electron main process 管理的本机绑定表；renderer、模型上下文、日志和 Git 不保存绝对路径。
- 规则：目录绑定与目录内容读取是两个权限动作，默认不扫描、不复制、不修改原目录。

### 2.6 重复 UAT 应保留结论，不保留全部副本

- 问题：同一桌面 UAT 在修复过程中生成上百个目录，增加空间占用和 AI 检索噪声。
- 规则：保留最终通过的完整 UAT，以及少量不可替代的真实外部连接证据；中间失败截图只在对应复盘中记录问题与根因。
- 规则：临时目录、旧解包目录和可重新生成的构建日志不作为长期证据。

## 3. 后续开发约束

1. 当前事实以源码、Git HEAD、最新规格和最新审查文档为准；历史 Phase 文档只作背景。
2. 新功能必须区分“已配置、已发现、已验证、可执行、已发布”五种状态。
3. 对话、工具调用、持久化和恢复必须有稳定 ID、明确所有权和可验证终态。
4. 用户数据、密钥、SAP evidence 和本机绝对路径不得进入 Git、截图或普通日志。
5. 每次发布只保留一个活动版本目录；旧版本依靠 Git tag、commit 和发布记录追溯。
6. 对抗式审查优先验证越权、串话、竞态、恢复、取消、失败回退和文档真实性。
