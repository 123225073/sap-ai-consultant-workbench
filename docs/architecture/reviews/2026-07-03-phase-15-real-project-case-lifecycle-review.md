# Phase 15 Real Project And Case Lifecycle Adversarial Review

## Scope

Phase 15 replaces demo-only UI creation with real local project and case lifecycle actions:

- create local project;
- create local case;
- switch project;
- switch case.

This phase does not add delete, upload, Feishu cloud publish, SAP write, generic SAP read, model IPC, shell execution, URL opening, or arbitrary file browsing.

## Multi-Agent Inputs

| Agent | Recommendation | Decision |
|---|---|---|
| Product/Roadmap evaluator | Do real local project and case lifecycle first. | Adopted. This is the foundation for daily use and for all later SAP/model/knowledge work. |
| Safety/Architecture pre-review | Document/knowledge ingestion firewall is a high-risk next area. | Deferred. Upload/parsing is still closed, so the safer first move is to finish real lifecycle while preserving no-upload guards. |
| Final adversarial reviewer | Fix state-load fallback, project.json-only stale metadata, and getState timestamp churn before commit. | Adopted. `loadOrCreateState()` now separates read/parse fallback from persistence errors, `shouldPersistActiveProjectMetadata()` detects stale project metadata, and the Phase 15 probe covers both metadata-only migration and stable repeated reads. |

## Threat Model

| Risk | Attack Or Failure | Mitigation |
|---|---|---|
| Path traversal | User enters `../escape`, `C:/temp`, `.env`, `.sap-adt-cli`, or internal JSON names as project/case text. | `assertSafeLifecycleText` rejects path-like and internal-state markers. IDs are generated by the main process, not accepted from the renderer. |
| ID coercion | Hostile renderer sends `project/abc`, `project:abc`, or traversal-like `projectId` / `caseId` that could be sanitized into a real ID. | Lifecycle switch/create-case inputs use strict ID validation and reject anything outside `^[A-Za-z0-9_-]{1,80}$`. |
| Concurrent writes | Double-clicks or concurrent IPC calls create projects/cases at the same time and overwrite each other. | `WorkspaceStore` serializes state-changing lifecycle methods with `runExclusive`; atomic JSON writes use unique temp files. |
| Cross-project case switching | UI or hostile renderer asks to open a case under the wrong project. | `switchCase` validates that the case belongs to the selected project. |
| Demo data leaks into real projects | New real project inherits demo knowledge, demo SAP URL, or demo API endpoint. | `createLocalProjectRecord` uses `createProjectKnowledge(id, false)` and blank non-secret configs. |
| Demo creation remains exposed | Renderer calls old demo creation APIs after real lifecycle ships. | Demo seed methods remain internal, but `workbench:create-demo-project` / `workbench:create-demo-case` are removed from main IPC, preload, and renderer types. |
| Ambiguous SAP version | New project uses `UNKNOWN` and silently receives the S/4 standards template. | New project creation rejects `UNKNOWN`; the UI only offers `S4` and `ECC`. |
| Stale storage metadata | Config center, `app-state.json`, or `project.json` shows an old case directory after case creation, switching, or legacy state normalization. | `localStorage.casesDir` is synchronized to the active case during creation and switching. `loadOrCreateState()` persists normalized stale storage metadata back to `app-state.json` and `project.json`. |
| State fallback data loss | A metadata write failure during `getState()` is treated like a missing or corrupt state file and overwrites `app-state.json` with an empty state. | `loadOrCreateState()` only initializes empty state when `app-state.json` is missing or cannot be parsed. Persistence failures from `saveState()` or `writeProjectMetadata()` now propagate instead of entering fallback initialization. |
| Project metadata drift | `app-state.json` is correct, but the active project's `project.json` still points to an old case folder. | `shouldPersistActiveProjectMetadata()` reads active project metadata and rewrites `project.json` when its storage metadata differs from normalized state. |
| Read-time timestamp churn | Repeated `getState()` calls change `config.updatedAt` or `localStorage.lastCheckedAt` even when no project data changed. | `sanitizeProjectConfig()` preserves existing timestamps and `normalizeLocalStorageConfig()` only changes storage metadata when it needs to repair a project/case path. |
| Knowledge auto-publish | New project/case creation accidentally creates published knowledge. | Lifecycle methods only create project/case metadata and empty knowledge. No knowledge status is set to `published`. |
| SAP or Feishu side effects | Creating or switching local objects triggers SAP, model, Feishu, CLI, or network work. | No connector calls are in lifecycle methods. Security preflight scans lifecycle paths for dialogs, shell, network, openers, and delete markers. |
| Search misdirection | New projects/cases are not searchable, or search points to wrong active case. | Lifecycle methods refresh search. The probe verifies created project/case search results. |

## Positive Capability List

Allowed:

- local JSON state updates under `local-data/workbench`;
- generated project ID and case ID;
- generated project/case directories under the workspace local data root;
- default project standards copy;
- empty project knowledge store;
- current project/case switching.

Blocked:

- SAP write, SAP SQL, SAP browser, generic object search;
- Feishu create/update/publish/auth flow;
- document upload or parsing;
- arbitrary path read/write;
- deletion;
- model execution outside the existing safe `append-message` path.

## Verification Targets

- `scripts/phase15-real-project-case-lifecycle-probe.mjs` proves real creation, concurrent creation, switching, search, strict ID rejection, `UNKNOWN` rejection, demo IPC removal, storage metadata sync, legacy state storage migration, project.json-only migration, repeated `getState()` timestamp stability, and hostile input rejection.
- `scripts/security-preflight.ps1` whitelists only the four new narrow IPC channels and checks lifecycle safety markers.
- Existing Phase 11-14 probes prove no regression to safe model context, SAP read-only evidence, real ADT fixed GET, and local-only Feishu handoff.

## Residual Risk

Document upload and knowledge parsing remain intentionally closed. The next phase should add a document ingestion firewall before any real Word/Excel/PDF/CSV import is allowed.
