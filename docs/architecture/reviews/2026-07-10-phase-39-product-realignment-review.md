# Phase 39 产品重整审查记录

日期：2026-07-10

## 审查目标

确认本轮不是单纯换皮，而是真正修复主路径、模型渠道和安全行为之间的不一致。

## 开发前基线

| 检查项 | 基线结论 |
|---|---|
| Product / Case / Chat 定位 | 文档方向清楚，UI 默认入口和部分行为未完全落实 |
| 多渠道配置 | 数据结构支持最多 6 个，UI 只操作第一个 |
| 模型列表 | 渠道保存完整列表，案件只允许探针模型 |
| 权限模式 | 案件动作使用选择值，普通案件对话硬编码为请求批准 |
| 三栏布局 | 固定宽度总和会在 Windows 缩放下横向裁切 |
| 主输入区 | SAP 取证、案件动作、权限、Codex、模型和未开发按钮同时常驻 |
| 安全边界 | SAP 只读、密钥存储和 renderer/main 隔离基础可靠 |
| 基线验证 | `npm run check`、`npm run build` 和 Phase 27-38 probes 通过 |

## 完成后记录

### 实际结果

- 主工作台默认进入 Work；新建表单、SAP 取证和右侧文件区均按需显示。
- 案件动作收敛为一个选择器和一个生成按钮，权限收敛为单一选择器；无行为的附件、语音和开发期控件已移除。
- 配置中心支持最多 6 个独立模型渠道；渠道验证后保存完整模型列表，对话可按渠道选择任意已获取模型。
- 渠道验证资格由 main process 持有，renderer 不能通过保存配置伪造模型列表、验证状态或测试模型。
- 已保存密钥不再回传 renderer；输入只用于本次保存，随后清空。
- Daily Chat 在任何外部模型调用前完成输入解析和清洗；空响应不能通过模型验证。
- SAP 仍只有只读接口，跳过证书校验只在用户明确配置时生效，不再静默降级。
- 搜索结果可打开目标，隐藏 Project 可恢复，知识详情在窄窗口仍可访问。
- 应用启动窗口会按显示器可用工作区收敛，避免 Windows DPI 缩放导致窗口超出屏幕。
- 案件动作已与真实产物对齐：资料梳理、案件笔记和交付整理生成专属文件，开发说明、流程图和候选知识沿用既有专属产物。
- Daily Chat 可选择当前 Project 已授权渠道中的任意已获取模型；main process 再次验证渠道资格和模型清单，消息仍只进入独立 Chat。
- 独立 UX 对抗审查发现的输入区拉伸、Daily Chat 无模型选择、SAP 未验证假可用、配置页包屑、重复搜索入口和 1180px 断点冲突已修复并复测；AI 保存与测试按钮也已移到高级设置之前。

### 残余风险

- 第二个真实外部模型渠道仍需要用户自己的地址和凭据做现场连通测试；自动化已覆盖多渠道保存、隔离和资格校验。
- Daily Chat 当前复用活动 Project 的授权渠道；后续个人级渠道注册表完成后，Chat 才能完全不依赖活动 Project。
- 配置页表单仍较长；AI 保存与测试已前置，但在更低窗口高度下仍可能需要滚动，后续可继续压缩字段间距。
- `App.tsx` 和 `ConfigCenter.tsx` 仍偏大，后续拆分时必须保持现有 IPC 和安全边界不变。
