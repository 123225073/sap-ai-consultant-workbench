# Phase 42 正式发布加固审查

审查日期：2026-07-11

## 结论

Phase 42 已消除内部试用版中最主要的代码级发布阻塞，但在取得组织代码签名证书、正式品牌资产和严格 SAP 证书验证前，仍不能宣称“正式对外发布通过”。

## 已完成

1. 开发说明书采用动作专用模型契约，校验业务背景、范围、方案、SAP 对象、逻辑、权限、异常、测试、上线回退和待确认事项。
2. 流程图只接受通过安全校验的 Mermaid；禁止外部链接、脚本和 SAP 写入动作，失败时生成案件专用待确认骨架。
3. 梳理资料、沉淀笔记和整理交付物读取真实案件对话和文件清单，不再输出固定占位清单。
4. 重复生成成果时，旧文件进入 `snapshots/versions/`，避免静默覆盖。
5. 状态升级采用显式 schema 版本、未来版本拒写和升级前快照；版本检查先于 SQLite 缓存初始化。
6. 提供完整本地备份和受控旧工作台导入，带 SHA256 manifest；导入前保留当前安装版完整备份。
7. 所有知识候选必须人工审核；发布时由后端重新检查 SAP 对象和适用期冲突。
8. 模型改为逐模型验证并累计可用模型；Work 和 Chat 只显示单独测试通过的模型。
9. 搜索按 `Project + Case + relativePath` 合并文件名和安全摘要，避免重复结果和同名误开。
10. 配置、规范、知识和对话草稿增加离开保护；成果动作改为紧凑浮层，不再推动输入区布局。
11. 新增 Phase 42 生产加固探针，覆盖成果版本、完整备份、受控导入和未来版本拒写。
12. 新增 `npm run release:win:signed` 正式发布命令；Git dirty、缺少证书、签名无效或缺少可信时间戳时直接失败。

## 仍需外部完成

1. 提供组织认可的 Windows 代码签名证书和可信时间戳服务。
2. 提供经品牌与法务确认的正式应用图标、发布主体和 SAP 商标使用口径。当前项目名称不等同于 SAP 官方背书。
3. 将生产 SAP 连接切换到严格证书校验；跳过证书模式只能用于受控内网。
4. 在干净 Windows 用户上完成签名安装包的首次安装、升级、回退和卸载保留数据验收。
5. 若要在应用内创建或发布 Feishu/Lark 云文档，需另行设计授权、内容预览和操作时确认；当前仍只生成本地交接草稿。

## 验证命令

```powershell
npm run verify
npm run package:win
npm run release:win:signed
```

其中第三条必须在配置 `CSC_LINK` 后执行，并且只接受干净 Git 工作区。
