# 多 Agent 执行模型

日期：2026-07-15

本文区分两类容易混淆的 Agent：

- **开发协作 Agent**：用于本仓库研发、审查和测试，由当前开发主控分派。
- **产品运行时子 Agent**：未来由 SAP AI 顾问工作台自己的 Agent Runtime 创建，用于一个用户任务内的有限并行工作。

两者共享“边界先于并行”的原则，但不共享线程、权限或数据。

## 1. 总原则

多 Agent 的目的不是“同时开很多线程”，而是用清晰边界减少等待和返工。

本项目采用：

```text
主控 Agent
  -> 冻结目标、边界、共享契约
  -> 分派独立 Agent
  -> 审查结果
  -> 合并代码
  -> 运行验收
```

## 2. 什么必须串行

以下内容必须由主控 Agent 串行推进，不能并行乱改：

| 内容 | 原因 |
|---|---|
| MVP 边界 | 防止做成团队 SaaS 或通用 Dashboard |
| 安全规则 | 防止密钥、SAP 源码、客户资料进 Git |
| 数据模型 | 后续所有模块都依赖它 |
| 案件目录结构 | 文件树、搜索、知识候选都依赖它 |
| IPC 和服务边界 | 防止 UI 直接读密钥、直接拼命令、直接操作 SAP |
| UI 总布局 | 必须保持 Codex 风格，不做卡片式后台 |
| 密钥策略 | 必须先确定安全存储和 `secret_ref` |
| ADT 只读策略 | 防止后续误加写入、激活、传输释放 |

## 3. 什么可以并行

只有在前置契约冻结后，才允许并行：

| 前置条件 | 可并行任务 |
|---|---|
| 安全边界完成 | README、架构文档、安全审计 |
| 数据模型冻结 | 项目服务、案件服务、文件服务 |
| App Shell 完成 | 左侧栏、中间对话、右侧文件、底部输入 |
| 配置契约冻结 | ADT 配置、飞书配置、API 配置 |
| 连接器接口冻结 | ADT 只读连接器、飞书 CLI、模型 API |
| 案件文件规则冻结 | 搜索、知识候选、文件树读取 |

## 4. Agent 角色

| Agent | 责任 | 不允许做 |
|---|---|---|
| 主控 Agent | 范围、接口、合并、验收 | 不跳过审计 |
| 产品/UX Agent | 检查界面是否符合 SAP 顾问工作流和 Codex 风格 | 不擅自加营销页 |
| 桌面壳 Agent | Electron 应用启动、窗口、preload | 不写业务连接器 |
| 数据 Agent | SQLite、项目、案件、文件索引 | 不处理真实 SAP |
| 案件文件 Agent | 文件夹生成、文件树读取 | 不越权写到案件目录外 |
| 配置 Agent | 配置中心 UI 和状态 | 不保存明文密钥 |
| 连接器 Agent | ADT、飞书、模型 API 包装 | 不实现 SAP 写入 |
| 规范 Agent | 项目规范副本、差异、版本 | 不改全局模板污染项目 |
| 知识/搜索 Agent | 候选知识、人工确认、检索 | 不自动正式入库 |
| QA/安全 Agent | 测试、敏感扫描、对抗式审计 | 不只看表面绿灯 |

## 5. 每个功能的合并门禁

每个功能必须经过：

1. **规格审计**：是否符合产品文档和当前阶段范围。
2. **安全审计**：是否泄露密钥、客户数据、SAP 源码或越过只读边界。
3. **体验审计**：是否让 SAP 顾问更好完成案件，而不是堆功能。
4. **可验证审计**：是否有命令、测试、截图、文件或运行结果证明完成。

## 6. 产品运行时子 Agent 模型

产品运行时采用父子 Thread，而不是让多个 Agent 共同改写一份聊天数组：

```text
Parent Turn
  -> Task Graph
    -> Explorer Thread
    -> SAP Evidence Thread
    -> Document Builder Thread
    -> Reviewer Thread
  -> Structured Results
  -> Parent Synthesis
```

| 规则 | 默认值 |
|---|---|
| 创建条件 | 任务确实可独立并行，普通问答不创建 |
| 最大并发 | 3 |
| 最大深度 | 1 |
| 权限 | 继承父 Thread，不能扩大 |
| 上下文 | 只传任务所需摘要、引用和范围，不复制全部历史 |
| 返回 | 结论、证据引用、产物、失败原因和未解决问题 |
| 失败策略 | 单个子任务失败不伪装成功；由父任务决定降级、重试或请求用户 |

推荐的第一批角色：

| 角色 | 责任 | 禁止 |
|---|---|---|
| Explorer | 检索案件文件、已审核知识和公开资料 | 不写案件文件，不读取密钥 |
| SAP Evidence | 在确认的项目和连接范围内做只读取证 | 不写 SAP，不自动跨系统扩大范围 |
| Document Builder | 根据已确认事实生成开发说明书或 Mermaid | 不把草稿标为已验证事实 |
| Reviewer | 独立检查证据、规范、安全和交付完整性 | 不修改原始证据，不替用户批准高风险动作 |

每个子任务必须有稳定 ID、输入范围、预算、超时、父任务引用和终态。父任务只接收结构化结果，详细事件保存在子 Thread 中，避免把所有过程污染主上下文。

## 7. 当前执行策略

仓库基础、主要产品页面和独立 Agent Runtime 的 Phase 50-56 基线已经完成多轮开发。当前产品已具备事件账本、Provider 适配、本地内置只读工具循环、上下文预算、checkpoint、Skills、声明式 Plugin 与 MCP 连接发现；产品运行时子 Agent 仍属于后续受控能力，不能在当前版本中宣称可用。

开发协作仍可并行做官方资料研究、独立代码审查和测试，但公共事件模型、权限策略、迁移规则和 IPC 合同由主控串行冻结。历史拆解见 [Phase 50 计划](../superpowers/plans/2026-07-15-phase-50-independent-agent-runtime-foundation-plan.md)，当前事实以源码、Phase 50-56 探针和最新 review 为准。
