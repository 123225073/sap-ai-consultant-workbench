# ADR 0003：客户项目、运维项目与对话线程三级结构

- 状态：已接受
- 日期：2026-08-03

## 背景

旧界面把底层 `Project`、`Case` 和 `WorkThread` 都混合展示为“项目”“工作文件夹”或“任务”，并用一个默认“收件箱”维持初始状态。这不符合 SAP 日常运维的真实组织方式，也导致新增线程时重复选择文件夹。

## 决策

产品统一采用以下用户模型：

1. 客户项目（底层 `Project`）：代表公司或客户，拥有 SAP ADT landscape、规范和知识。
2. 运维项目（底层 `Case`）：代表该客户下的一项持续工作，并拥有一个共享本地文件夹。
3. 对话线程（底层 `WorkThread`）：代表运维项目内的一次独立对话。兄弟线程共享运维项目文件，但聊天记录独立。

SAP ADT 配置按客户项目隔离。AI 模型渠道、API Key、Feishu/Lark CLI 和 Codex CLI 是个人工作台全局配置，在所有客户项目之间共用。

空的默认“收件箱”不再作为用户概念展示。为兼容旧状态可以保留不可见内部占位对象；若旧收件箱已有真实内容，必须保留并显示为“未归类工作”。

## 结果

- 新建运维项目时只绑定一次本地文件夹。
- 在运维项目下点击 `+` 直接创建新对话线程，不再打开文件夹选择器。
- 新线程先使用“新对话”，首条用户消息写入后自动生成标题。
- 同一运维项目的线程可以通过受控只读工具列出和读取兄弟线程的有限上下文；不得跨运维项目读取。
- 代码层暂时保留 `Project`、`Case`、`WorkThread` 名称以避免破坏存储兼容，用户界面和文档使用新的领域语言。
