# ADR 0004：对话回退采用可恢复分支

- 状态：已接受
- 日期：2026-08-04

## 背景

用户需要像 Codex 一样编辑较早发出的消息并重新发送。如果直接原地修改或删除消息，会破坏对话可追溯性，也可能让旧 checkpoint 把已经回退的内容重新带入模型。Work 对话还会生成共享文件，聊天记录和项目成果不能被混为同一个回退范围。

## 决策

1. 编辑历史用户消息时，先把当前线程的完整消息保存为可恢复版本。
2. 当前活动对话从目标用户消息开始截断；编辑后的消息作为新回合重新发送，不修改旧消息的历史事实。
3. 恢复任一历史版本前，也先保存当前活动分支，因此恢复操作本身可以撤销。
4. 回退或恢复后撤销该线程已有 checkpoint，下一回合基于新的活动消息重新构建上下文。
5. Agent Runtime 记录 `conversation-rewind` Item，用户可见的 `conversation.md` 只投影当前活动分支。
6. Work 的共享运维项目文件、证据和交付物不随聊天回退自动删除、覆盖或恢复；需要调整文件时由用户另行明确操作。
7. 每个线程最多保留 12 个本地对话版本，防止状态无限增长。

## 结果

- 用户可以修改历史要求并从该位置继续，同时保留原对话和当前分支的恢复入口。
- 模型不会继续读取已被回退的后续消息或旧 checkpoint。
- 对话上下文回退与共享项目文件生命周期保持清晰分离。
- 这不是多人协作式 Git 分支，也不自动回滚 SAP、外部系统或本地成果文件。
