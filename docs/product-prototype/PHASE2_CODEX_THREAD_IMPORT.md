# 第二期：Codex 线程导入

状态：保留设计，当前稳定版不开发。

该功能是外部历史迁移工具，不属于独立 Agent Runtime。即使未来实现，也只能消费用户主动选择的稳定导出文件或官方接口，不能让核心会话恢复依赖 Codex 内部数据。

## 结论

Codex 线程导入有明确价值，但不应直接读取 Codex App 的内部数据库。内部存储格式不是稳定的产品接口，直接耦合会带来版本兼容、隐私泄露、重复导入和数据损坏风险。

当前版本优先保持 Work、Chat、SAP 只读、成果文件、规范和知识库稳定。真实使用一段时间后，再基于导出文件或官方稳定接口实现导入。

## 第二期建议流程

1. 用户点击“导入 Codex 对话”。
2. 先选择目标 Project。
3. 选择导入到已有 Case，或创建一个新的 Case。
4. 选择 Codex 导出的线程文件或导出目录；不直接扫描内部数据库。
5. 系统显示预览：线程标题、时间、消息数量、附件数量和敏感内容提示。
6. 用户勾选需要导入的线程。
7. 系统再次显示目标 Project / Case、预计新增文件和不会导入的内容。
8. 用户确认后执行导入。

## 默认安全边界

- 默认只导入用户消息和助手最终回复。
- 不导入 API Key、密码、Token、环境变量、终端完整日志或隐藏系统提示。
- 工具调用只保存简短结果摘要，不保存原始命令输出。
- 附件不自动复制；需要逐项确认并经过文件类型与敏感内容检查。
- 每个源线程计算指纹，重复导入时提示并默认跳过。
- 保留原始时间、来源线程 ID 和导入时间，不能伪装成工作台原生对话。
- 导入失败时不得产生半个 Case；应先写入临时目录，校验后再提交。

## 文件落点

- 对话追加到目标 Case 的 `conversation.md`。
- 来源和导入审计写入 `technical/codex-import-manifest.json`。
- 用户确认保留的附件进入 `evidence/imported/`。
- 不自动进入正式知识库；仍需经过候选知识和人工审核流程。

## 开发前提

满足以下条件后再进入开发：

1. 当前版本完成一段时间的真实使用和数据稳定性观察。
2. 明确 Codex 可用的官方导出格式或稳定接口。
3. 至少准备三种真实但已脱敏的导出样本。
4. 冻结重复导入、附件、工具日志和敏感内容处理规则。
5. 完成导入前预览、用户确认、回滚和跨版本测试设计。
