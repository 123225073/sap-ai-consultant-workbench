审查日期：2026-07-16

> 历史审查：本文记录当时按“组织签名正式发布”口径进行的门禁审查。用户随后明确产品是个人独立工具，代码签名、品牌法务清单和 SAP 授权不是普通构建及个人分发的技术前置条件。当前发布口径以 `README.md`、`docs/release/KNOWN_LIMITATIONS.md` 和 `docs/release/INTERNAL_PILOT_RUNBOOK.md` 为准；下文外部门槛只适用于可选的高信任签名发布档位。

## 结论

- **个人使用与小范围分发：工程验收通过。** 完整回归、独立 Agent Runtime 与能力中心专项探针、安全预检、连续三次桌面图形 UAT、Windows Setup/Portable 构建和打包后主程序启动均通过。
- **未签名分发限制已明确。** 本机没有 Authenticode 证书，因此 Windows 可能显示“未知发布者”或 SmartScreen 提示；这不阻止个人产品安装运行，但不能声称为高信任签名发行。
- **SAP 始终只读。** 本版本不提供写入、激活、传输、过账、删除或批量更新能力。

## 可选的高信任签名发布门禁

选择高信任签名发布档位时必须同时满足：

1. 提供组织认可的 Authenticode 证书，或配置 Windows 证书存储身份。
2. 提供经品牌与法务批准的 `release-brand-approval.json`。
3. 正式 ICO 必须包含 16、24、32、48、256 像素尺寸，且哈希与批准清单一致。
4. 产品名、发布主体、appId、安装包前缀必须与批准清单一致。
5. 独立产品不得在产品名、发布主体、appId 或安装包前缀中使用 SAP；SAP 授权模式必须提供书面授权记录编号。
6. 主程序、Setup、Portable 和实际安装后的卸载器必须由同一证书签名，并带可信 RFC 3161 时间戳。
7. 在干净 Windows 发布主机完成安装、卸载、签名和残留检查。
8. 使用受控测试账号完成 SAP 严格证书只读、模型渠道和 Feishu/Lark 登录态复测。

正式构建命令：

```powershell
npm run release:win:signed:preflight
npm run release:win:signed
```

缺少任一外部输入时，命令必须失败，不能生成“看起来像正式版”的未签名产物。

## 桌面自动化结论

Electron CDP 桌面 UAT 已提供稳定、可重复的 renderer 截图、DOM 与可访问性断言、preload IPC、落盘成果哈希和生命周期日志。Computer Use 也已真实启动打包后的 `SAP AI 顾问工作台.exe` 并识别到独立窗口；当用户正在操作或窗口被最小化时，自动化会按安全策略停止前台控制，这不代表应用闪退。

## 仍需按使用环境确认的事项

1. 用户首次分发时接受未签名程序可能出现的 Windows“未知发布者”提示；如需消除此类提示，再选择可选的 Authenticode 签名档位。
2. 在每个实际使用网络中分别复测 SAP、模型渠道和 Feishu/Lark；外部服务状态不能由本地构建永久保证。
3. SAP 跳过证书校验连接在每次真实验证前都必须由用户确认；应用不会静默发送 SAP 凭据。
