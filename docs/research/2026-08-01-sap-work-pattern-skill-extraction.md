# 旧 SAP 工作目录高频工作模式与内置 Skills 提炼

> 状态：**个人场景样本（已被官方方法论研究替代为产品默认依据）**。本文件只说明旧工作区中哪些工作反复出现，不再定义内置 Skills 的标准流程。当前标准见 [中国 SAP 日常运维 Skills：官方方法论与一手资料研究](2026-08-01-sap-operations-official-methodology.md) 和 [SAP 运维 Skills 产品体系](../product-prototype/SAP_OPERATIONS_SKILLS.md)。

日期：2026-08-01

## 结论

旧 `SAP ABAP` 工作目录的核心价值不是某一份提示词或某一个脚本，而是一套反复出现的 SAP 顾问工作闭环：确认目标系统与当前基线、只读取证、跨对象或跨文件核对、定位根因、形成最小修改/处理方案、验证并沉淀交付物。

最初从个人工作样本提炼出的 5 个候选 Skills 为：

1. `sap-evidence-first-analysis`：证据优先问题分析。
2. `sap-abap-safe-change`：ABAP 安全改动与复核。
3. `sap-data-reconciliation`：SAP 数据、日志与表格对账。
4. `sap-development-spec`：开发说明书。
5. `sap-incident-closure`：事故闭环。

这些方向已被重构进 9 个标准化运维 Skills，不再作为最终 taxonomy；仍保留原 Skill ID 以兼容已有引用。

## 反复出现的痛点

### 1. 事实很容易过期或串系统

同一对象常同时存在测试、生产、历史导出和多次修复版本。只看本地最新文件名并不等于 SAP 当前事实。必须固定系统、Client、读取时间和对象，并区分实时证据与历史基线。

### 2. 真正耗时的是依赖追踪，不是写一段代码

日常问题常跨主程序、Include、函数、CDS/DDIC、接口、单位/币种、日志和上下游字段。单文件修改可能修复表象，却破坏事务、回归或其他调用者。

### 3. 数量、单位、币种、符号和聚合粒度容易造成“看似正确”

近期材料反复出现订单单位、基本单位、价格单位、已开票数量、冲销/退货、重复关联和跨月口径。对账必须先定义粒度与口径，再比较总数和明细。

### 4. 零散结论难以直接交付

业务需求、会议结论、当前系统事实、字段映射、代码建议和测试结论分散在聊天、源码、Excel 和文档中。说明书需要把它们转成一致、可开发、可验收的结构。

### 5. “修好了”不等于闭环

事故处理还需要时间线、影响、根因链、实际处置、验证、回退、遗留风险和候选知识。没有验证和证据来源时，只能标记临时止血或待验证。

## Skill 边界设计

| Skill | 主要输入 | 主要输出 | 不负责 |
|---|---|---|---|
| 证据优先问题分析 | SAP 只读证据、Case 文件、日志、用户描述 | 根因结论、证据矩阵、缺口清单 | SAP 写入、无证据定性 |
| ABAP 安全改动 | 当前源码、依赖、需求、测试材料 | 最小改动、审查结论、测试与回退 | 未确认的激活、传输、生产写入 |
| 数据对账 | Excel/CSV、日志、查询结果 | 汇总、异常明细、待确认/待处理清单 | 自动批量修数、执行宏或外链 |
| 开发说明书 | 需求、会议、现状证据、字段和规范 | 中文说明书、字段映射、测试矩阵、上线清单 | 编造生产现状、自动外部发布 |
| 事故闭环 | 事件、日志、变更和验证证据 | 闭环报告、时间线、候选知识 | 未审核的知识发布 |

## 没有复制进 Skills 的内容

- 真实 SAP 地址、账号、密码、Token、客户数据和源码。
- 只适用于某个客户、对象或临时事件的硬编码路径与规则。
- SAP 写入、激活、过账、传输和批量修改能力。
- 旧目录中的凭据切换脚本。连接应由工作台 Project 配置、安全存储和内置只读 Connector 管理，而不是由文本 Skill 持有。
- 大量相似历史输出。Skill 只保留可迁移的方法、检查点和模板。

## 后续候选（本轮不实施）

这些能力有价值，但旧目录中的实际频率低于首批闭环，建议用户确认优先级后再建设：

1. 业务蓝图/解决方案文档 Skill：AS-IS、TO-BE、Fit-Gap、组织与主数据、配置、集成、迁移和验收。
2. 流程图 Skill：业务流程、数据流、调用链和异常分支的受限 Mermaid 生成与导出。
3. 会议录音到需求基线：转写、口径冲突、决定/待确认项和版本变更。
4. 交付物一致性检查：Markdown、Word、Excel、流程图和飞书交接草稿之间的字段、版本和结论同步。
5. 可解释 Skill 路由：向用户显示“为什么命中、读取了什么、输出到哪里”。
